# ISSUES

- **UI cursor / capture** (`UserInterface.cpp`, `Window.cpp`): legacy `ui.capture()` uses `GLFW_CURSOR_DISABLED`; retained slider drag uses `GLFW_CURSOR_HIDDEN` via `requestUiCursorCapture`. Game + retained UI on one window still need a single owner if both want capture at once.
- **Unknown layout classes in Pong markup** (`Data/UI/pong-*.ui.html`): `column`, `align-stretch`, `fb200`, `minh0`, `justify-center` are not parsed by `UiAppFlex` nor defined in `flex.ui.scss` (real tokens: `col`, `b200`, `mh0`, `align-*`). Silently ignored; the bundle compiler should warn on unknown classes. Also `.score-readout { font-size: 48dp }` does not visibly apply. Same for SCSS properties: `UiStyleApplicationAdapter.cpp` only knows the `margin` shorthand (no `margin-left`/`-right`, no `auto` margins) and drops the rest silently; `Data/UI/simple-rts.ui.html` also uses the unknown `column` class.
- **Authored game screens, visual defects** (seen at 1920x1080 via `--agent-bridge` screenshots): Melon Audio Lab graph labels ("Com", "Hum", "Wi") are cut off at the right edge of the graph column and the "AUDIO LAYERS" section renders empty; Sound Analysis Lab frequency-axis labels are clipped the same way, its spectrogram sliders are ~40px wide, and the bottom help text runs off the sidebar instead of wrapping; Pong prints `AI difficulty 7.000000` (unformatted float) beside the Player 2 score, pushing that score off center.
- **Build warnings** (Debug x64, ~2,084): mostly C4244/C4245/C4267 conversions and C4100 unused params, which hide real ones. ~100 C4651/C4653 mean some files compile with options that differ from `OrkaPch.hpp`. `ULLUtil.cpp:19` and `QuadtreeNode.cpp:184` shift a 64-bit value by `64 - n`, which is UB when `n == 0`.
- **UiHost key routing** (`Window.cpp` `routeInput`, `UI/UiHost.cpp`): keyboard routing walks parents only, so a `UiHost` nested under a shell is skipped unless that host is focused. Cursor capture skips it too. When the host is reached, `keyInputCallback` consumes every key and `Window`'s Escape / Alt+Enter never run. When it is not reached, those `Window` hotkeys still run. A shell that also handles them in `keyInputCallback` must consume the same press in `inputEvent`, or the action runs twice (see `Pong.md`).
